# Implementation Plan: Clickstream Tracking Pipeline

**Branch**: `005-clickstream-tracking` | **Date**: 2026-05-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/005-clickstream-tracking/spec.md`

## Summary

Add a non-blocking analytics pipeline that silently captures app-launch connection events from the mobile client, routes them through a durable message broker to a background consumer worker, and persists per-platform aggregate counters. Exposes a health endpoint on the consumer and a read-only aggregates API on the gateway.

## Technical Context

**Language/Version**: Rust 1.75+

**Primary Dependencies**: actix-web, lapin (AMQP client), mongodb driver, serde, serde_json, futures-util, tokio

**Storage**: MongoDB (analytics aggregates) + PostgreSQL/PostGIS (existing application data)

**Testing**: cargo test

**Target Platform**: Linux server (Docker container)

**Project Type**: web-service (internal microservice: analytics-service)

**Performance Goals**: 100 connection events/sec sustained throughput; API response <200ms p95; aggregate query <500ms

**Constraints**: Client must never block; queue must survive broker restarts; health endpoint on consumer

**Scale/Scope**: Single consumer worker; analytics-service added to the existing Rust workspace

## Complexity Tracking

> **Justification for constitution violations**

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| RabbitMQ (message broker, deprecated in Principle I) | The pipeline requires a durable message queue to decouple the API gateway from the consumer worker. This is the core architectural pattern of the feature — synchronous processing would violate the non-blocking requirement (FR-002, FR-006). | Direct in-process channel (tokio::mpsc) would lose events on consumer restart and cannot survive gateway restarts, violating FR-003 (durable queue). Postgres LISTEN/NOTIFY lacks delivery guarantees and cannot buffer during consumer downtime. |
| MongoDB (not in LOCKED stack Principle II) | Per-platform connection aggregates (FR-005) are a simple key-value counter pattern. MongoDB's `$inc` atomic upsert maps directly to the requirement with zero schema overhead. | PostgreSQL upsert is possible but adds schema management overhead for a single collection with two fields. The aggregate data is write-heavy, read-rare — MongoDB fits the workload profile. |
